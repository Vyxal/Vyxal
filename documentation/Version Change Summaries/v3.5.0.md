# Vyxal 3.5.0

Vyxal 3.5 is a major update to Vyxal 3, with a new codepage, a refined command list, and a tidying-up of some of the syntax structures.

## New Codepage

The choice to move away from diacritics was inspired partly by people finding the diacritics "bland". But it also allows for more flexibility in what commands are assigned to characters. Indeed, with letters, it is harder to justify mnemonics for commands that are not related to the letter itself - you end up with a situation where `Ṃ` ends up performing `n ** -1` or `split on spaces`, neither of which really have anything to do with the letter `m`.

With symbols, metaphors are easier to derive, as meaning is inherently more abstract/subjective/open to interpretation. Ultimately, while programs might be slightly less readable, and not at all monowidthed, symbols lend themselves to a more flexible command set.

## Refined Command List

After the original Vyxal 3 release, it became clear that some important built-ins had been forgotten. In following releases, some were added back in, but there were still some key things missing. Therefore, in Vyxal 3.5, the command list has been redesigned from the ground up, making sure to add useful commands from Vyxal 2, and other golfing/array languages.

## Syntax Changes

There are some new syntax elements:

- `⎊` opens a structure that maps its code over permutations of the top of the stack.
- `⎋` closes a structure and pushes the first item of the result to the stack.
- `⍟` closes a structure and flattens the result.

Some syntax elements have been removed:

- There is no longer a decision structure. This used to be `Ḍ`.
- There are no longer any sugar trigraphs. While helpful for writing programs in all ASCII, there is no longer a neat way to map trigraphs to the wide variety of symbols in the new codepage. Additionally, literate mode is preferred for ASCII-only programs.

Some syntax elements have been slightly changed:

- Where `¤` used to act as a "context index" (Index into the list of context parameters), you now need to use `#¤`.
- Arguments in extension methods now have their type specified with a `:` rather than a `>`. For example, `#::+ cmd | lhs: num | #$lhs 2 +}` instead of `#::+ cmd | lhs > num | #$lhs 2 +}`.
- On the topic of extension methods, `.` can be used to indicate that the extension
  name overrides behaviour of a built-in. For example, `#::+ .+ | ...}` would override `+`. This extends to literate mode, which allows any keyword alias to be overridden for all other aliases. E.g. `extension .add | ...}` would also apply to `+` and `plus`.

## Other Changes

There are no longer separate "group next N elements as dyad" modifiers. Instead, grouping modifiers now calculate their arity based on the effective number of arguments popped. For example, `⑵++` would have an arity of 3, as the first `+` pops 2 arguments, and the second `+` pops an additional argument from the outer stack. You can always multiply a function by a number to force a specific arity.

There are less modifiers than the original Vyxal 3 release. This is because most times, a function overload achieves the same program length as a modifier + grouping modifier.

Complex numbers are no longer made with special syntax. Previously, `ı` was used as the complex number separator. Now, there is a `number, number` overload on the `j` built-in, which returns `(first number) + (second number)i`. Additionally, complex numbers are printed as `<real>j<imaginary>`. For example, `1 2 j` would print as `1j2`.

## New Website Design

This was mentioned in the 3.4.9 release notes, but it's worth mentioning again: the Vyxal 3 online interpreter has been completely redesigned. Courtesy of @gingershaped, the new layout is much more slick, and has a lot more features than the original TIO-esque layout (for example, test case suites, flags enabled via toggles, syntax highlighting, and auto permalink generation).

## Conclusion

It would be impractical to list all the new/changed elements in the release notes, as a lot was changed. Therefore, the best place to learn about the new commands is the [Information Table](https://github.com/Vyxal/Vyxal/blob/version-3/documentation/table.md). This should hopefully make the language much more substantial and feel more like a complete language. Which is good. Because that's what the intention was after all!
