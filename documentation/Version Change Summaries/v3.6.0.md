# Vyxal 3.6.0

With Vyxal 3.5.0 still being a new release, a flurry of bug fixes and new features were inevitable. If you feel like you've seen that said somewhere before, it could quite possibly be because I've written it before, in the notes for the last release in fact.

## String Compression Fix

It turns out that string compression using SSS had a few bugs:

1. `"` was being inserted into the compression result, making it impossible to decompress.
2. Some characters were inocrrectly being replaced before decompression.
3. Nelwines were being returned as the `◲` character.

These problems have all been fixed. If you have any strings from 3.5.1, you may need to recompress them using `#C`.

## Element Documentation Corrections

* A fair few descriptions have had typos/grammatical/accuracy errors have been corrected.
* The documented symbol for `sum` was previously listed as `Σ`. However, the implemented symbol was actually `∑`. This has been corrected in the documentation and in the codepage.
* The digits constant, `kd`, was incorrectly listed as `kb`. It has been remedied.
* The `#~` element has been removed, as it was a duplicate of the `æ` function overload.
* The function overload of `⧢` was previously undocumented. It has been added to the documentation.
* The scan and reduce modifiers were previously not documented at all.
* `k` constants have had their keywords changed to start with `@` and have all characters in uppercase. This was done to indicate that they are in fact representing k constants. Additionally, the uppercase naming reflects the tradition of using allcaps for constants in programming languages.

## New Elements

* `∆∧` - `bitwise-and` - Performs a bitwise AND on two integers.
* `∆∨` - `bitwise-or` - Performs a bitwise OR on two integers.
* `∆¬` - `bitwise-not` - Performs a bitwise NOT on an integer.
* `∆⊍` - `bitwise-xor` - Performs a bitwise XOR on two integers.
* A whole bunch of `k` constants, most taken from Vyxal 2.
* `#w` - `nest` - If the top of the stack is a scalar (function/number/string), wrap it in a list, otherwise do nothing.

## Element/Modifier Behaviour Changes

* `ℂ` (as `fixpoint-collect` given a `function`), now returns the last element of the fixed point sequence, rather than the entire sequence.
* `‰` now performs `flatmap` when given a function and a physical value.
* `⟒` (as `left-fork:`) now has support for a monad as the first element.
* `⧖` (as `map-over-permutations` given a `function`) now considers items in permutations of a string to be strings, rather than a list of characters.
* `±` now has a string overload that returns the case of each character.
* `◌` now has a string overload that returns whether a character is lowercase.

## Interpreter/Under-the-Hood Changes

* Better errors are given when a modifier is used with elements with unsupported arities.
* There are now tests to ensure that the codepage is consistent with the documentation, and that the documentation is consistent with the implemented elements.
* Some element implementations have been simplified by @ysthakur.
* `ʎ`, the character for `filter lambda` was not in the codepage, while its previous characer was in the codepage. This has been fixed.
* The `M`, `m`, `Ṁ`, `R`, `1`, `2`, `3`, `j`, `S`, `s`, and `L` flags were removed.
* You can now have the string `"|"` (or any other literate mode branch keyword) in a lambda without an error. E.g. `{"|"}` used to error, but now it doesn't.
